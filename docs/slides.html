課題

自分の「当たり前」は、
自分では見えない。

見えるのは、違う考えに触れたときだけ。

でも — 違う考えに触れる場所は、いま、いちばんそれを必要とする人にとって 安全ではありません。

誰のためのサービスか

自分の中で考えすぎる人。
人に気を使いすぎて、
言いたいことを飲み込む人。

会議で違和感を持っても「まあいいか」で終わらせてしまう

友達が誰かの悪口を言っているとき、否定も肯定もできず黙る

SNSに書こうとして、投稿する直前に全部消す

その人にとって、いまある場所は効かない

SNS・掲示板 自分に宛てて返信が来る。自分に向けて言われると身構えるし、 名前を出して表明した意見は引っ込めにくい
名言アプリ 受け取って終わり。自分の側は何も動かない
日記アプリ 自分の中だけで完結する。自分の当たり前は、自分では見えない
人に相談する 相手にも気を使う。そもそもそれができない人の話をしています

必要なのは、自分と関係のないところで生きている、他人の世界にふれること。

このサービスの価値

誰の

自分の中で考えすぎる人。

どんな課題を

自分の当たり前が見えない。
それに気づける安全な場所がない。

どう解決し

誰にも宛てられていない他人の言葉が、1日1回だけ届く。
心が動いたら書く。返信も評価も来ない。

どんな効果があるか

自分の当たり前が見える。さらに、自分の言葉が誰かの当たり前を動かしたことが返ってくる。

内容は、全部違います。

残っているのは「この言葉がなければ、この言葉は生まれなかった」という関係だけ。

リツイートは、内容が変わらずに広がる。

ここでは、内容が変わらないと成立しない。

転送ボタンを置いていないのではなく、
転送が原理的に不可能な構造です。

独自性は、1カラムに集約されている

parent_word_id

血統でも継承でもなく、「この言葉がなければ、この言葉は生まれなかった」を記録する。

名言アプリ 持っていない
日記アプリ 持っていない
匿名SNS 持っていない
ことづて 4世代の系譜が、再帰クエリ1回で取れる

アーキテクチャ

Server Components と Server Actions で、APIサーバーなしの1プロジェクト構成。
ブラウザからDBへの直接アクセスはなく、SQLは全部サーバー側に閉じています。

データ構造 — テーブルは3つだけ

偉人の言葉もユーザーの言葉も、同じテーブルに同じ形式で並びます。
「誰もが思想家になりうる」という思想を、データ構造で表現しました。

工夫・苦労した点

  1. 引用の正しさを、データ構造で担保した

    48件すべて原典から手作業で採取。全件に出典URL、訳出27件に原文を併記。 実行時にAIは1回も呼んでいない。

  2. 抽選を、運任せにしなかった

    初めての1語は必ず来歴つき。配信回数の少ない言葉を優先し、 書いた言葉が誰にも読まれずに沈まないことを保証。

  3. 紙を捨てて、点と線にした

    最初は手紙のメタファーで作り、途中で全部捨てた。 ことづては口頭で運ばれる言葉で、紙ではないから。

できていること

  • 3画面 + デモ用画面すべて実装済み、本番にデプロイ済み(Vercel + Supabase)
  • 偉人の言葉48件、全件に出典URL、訳出27件に原文を併記
  • 4世代の系譜が、モックではなく実データで動いている
  • 実行時にAIを呼ぶ処理はゼロ。配信も抽選も来歴もSQLだけ
