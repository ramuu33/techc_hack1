ひとつの言葉が、別の誰かの言葉を生んでいく場所。

はじまり

「掃除しろ」
「普通はやるものでしょ」

母と、何度も衝突しました。

整理してみると

家は回復する場所

— 私の前提

家は共同生活の基盤

— 母の前提

掃除の問題ではなく、前提がズレていただけだった。

価値があったのは、
自分の当たり前が、初めて目に見えたこと。

そしてそれは、一人で考えていても絶対に出てこなかった。

誰のためのサービスか

自分の中で考えすぎる人。
人に気を使いすぎて、
言いたいことを飲み込む人。

その人に必要なのは、自分に宛てられた返信ではない。

宛てられた言葉には防御が立つ。

名前を出して表明した意見は、引っ込めにくい。

必要なのは、自分と関係のないところで生きている、
他人の世界にふれること。

このサービスが集めるもの

名言ではありません。言葉と、それによって動いた自分です。

集めるもの 誰が読まれるか 言葉の行き先
名言アプリ 偉人の言葉 偉人のみ お気に入り一覧
SNS 投稿・反応 目立つ人 流れて消える
日記アプリ 出来事・感情 本人のみ 非公開の記録
ことづて 言葉 + それで自分がどう動いたか 誰でも 次の誰かに届く

内容は、全部違います。

残っているのは「この言葉がなければ、この言葉は生まれなかった」という関係だけ。

リツイートは、内容が変わらずに広がる。

ここでは、内容が変わらないと成立しない。

転送ボタンを置いていないのではなく、
転送が原理的に不可能な構造です。

アーキテクチャ

Next.js の Server Components と Server Actions で、APIサーバーなしの1プロジェクト構成。
ブラウザからDBへの直接アクセスはなく、SQLは全部サーバー側に閉じています。

データ構造 — テーブルは3つだけ

偉人の言葉もユーザーの言葉も、同じテーブルに同じ形式で並びます。
「誰もが思想家になりうる」という思想を、データ構造で表現しました。

独自性は、1カラムに集約されている

parent_word_id

血統でも継承でもなく、「この言葉がなければ、この言葉は生まれなかった」を記録する。

名言アプリ 持っていない
日記アプリ 持っていない
匿名SNS 持っていない
ことづて 4世代の系譜が、再帰クエリ1回で取れる

工夫・苦労した点

  1. 引用の正しさを、データ構造で担保した

    48件すべて原典から手作業で採取。全件に出典URL、訳出27件に原文を併記。 実行時にAIは1回も呼んでいない。

  2. 抽選を、運任せにしなかった

    初めての1語は必ず来歴つき。配信回数の少ない言葉を優先し、 書いた言葉が誰にも読まれずに沈まないことを保証。

  3. 紙を捨てて、点と線にした

    最初は手紙のメタファーで作り、途中で全部捨てた。 ことづては口頭で運ばれる言葉で、紙ではないから。

宛てられると防御が立つ。だから誰にも宛てられない構造にしました。

これから作りたいもの

再会

同じ言葉が数年後にもう一度届いたとき、当時の自分が書いた言葉を添えて見せる。
過去の点と今の点が、同じ言葉の上で向き合う。

軌跡というメタファーの完成形で、実装は既存データを引くだけです。

いま、この場で私が書いた言葉は、
明日、誰かのもとに届きます。

このサービスは、対立を解決する道具ではありません。
できるのは、衝突が起きる前に、自分の前提が見える機会を1日1回つくることだけです。

それで十分価値があると、私は思っています。
